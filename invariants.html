Security invariants

Written down so they can be argued with, and tested rather than believed.

Every control in this project fails open. A firewall rule that silently didn’t load, a flag a CLI quietly stopped accepting, a header that stopped being stripped — each looks exactly like a working control right up until it matters. Features announce their own breakage; boundaries do not. So the boundary gets its own tests, and they are written as attacks.

The invariants

#InvariantTested by
1Credential — the guest never receives long-lived provider credentials, and cannot smuggle its own to an upstream.test_invariants.py, adversarial.sh
2Host-control — the guest cannot modify or read the authoritative host egress policy, even as root.adversarial.sh
3Claude — the /claude route is unavailable unless the CLI is verified to suppress host-side tools and MCP.test_gateway.py
4Ollama — the guest cannot reach model management, however the path is spelled, nor use Ollama as a host-side network pivot.test_invariants.py, adversarial.sh
5Egress — access is denied unless permitted by current host policy; an allowlist entry names a service, not an address.test_egress_allowlist.sh, test_egress_profiles.sh
6Reboot — a host reboot creates no period of unintended guest internet access.adversarial.sh after a reboot (see gaps)
7Workspace — files produced by the guest are treated as untrusted until reviewed.adversarial.sh
8Warden — guest code cannot self-authorize an egress window; it can ask, only a human grants.test_warden_scope.py, adversarial.sh
9Budget — a compromised agent cannot exceed configured spend limits indefinitely.test_budget.py
10Reporting — Kagebox never claims a posture it did not observe.test_setup_posture.sh
Why #10 is on the list

setup used to print egress: contained unconditionally, so a declined sudo prompt still ended with a reassuring green banner. A boundary you believe in but do not have is worse than a known-open one.

Running them

# Offline half — no VM, no sudo, no network. Runs in CI on every push.
python3 tests/test_invariants.py     # attacks the pure boundary logic
python3 tests/test_gateway.py        # bridge containment
python3 tests/test_warden_scope.py   # the warden cannot be talked into granting
python3 tests/test_budget.py         # spend caps
bash    tests/test_egress_allowlist.sh
bash    tests/test_egress_profiles.sh
bash    tests/test_setup_posture.sh

# Live half — needs a provisioned, running VM.
bash tests/adversarial.sh
./kagebox verify

adversarial.sh attacks from inside the sandbox: it tries to read the host ruleset, flush its way out, reach non-allowlisted destinations over v4 and v6, find a credential, see a host process or socket, open /dev/kvm, and open its own door.

Known gaps

A suite that looks complete is worse than one that admits its edges.

  • Reboot ordering is not automated. The egress unit is ordered before multipassd, but nothing here reboots a host to prove it.
  • The port-scoping probe is weak. A refusal on an unlisted port doesn’t prove the firewall caused it — the remote may simply not listen there.
  • No agent-level injection tests. Prompt injection from a web page, a workspace/ file, a malicious skill or package is the category most likely to matter in practice and the least covered.
  • CDN fronting is unaddressed by design, not omission. An IP allowlist cannot separate a hostname from its neighbours on a shared front end.
  • The suite runs as the operator, not as an attacker with a 0-day. It tests the controls as designed; it does not attempt hypervisor escape.

If you fix a boundary bug, add the attack that would have caught it. A regression test written after the fact is the only part of the fix that keeps working. The current version lives in INVARIANTS.md.
