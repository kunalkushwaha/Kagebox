Threat model

What is protected, what is not, and where the edges are.

This project runs an autonomous agent — software that executes arbitrary shell commands, edits files, installs packages and drives a browser — inside a sandbox, so that a misbehaving or prompt-injected agent cannot harm your host.

The agent can be steered by the model making mistakes, and by prompt injection: malicious instructions hidden in a page, file or message it reads. Assume it may attempt anything its tools allow. The sandbox’s job is to bound the blast radius.

What is protected

BoundaryMechanismResult
Host filesystemKVM microVM with only workspace/ mountedThe agent cannot read or write your files, except the one shared folder.
Host kernelHardware-virtualised VM, not a shared kernelAn escape needs a hypervisor breakout, not a container escape.
CredentialsKept on the host, injected by the bridge; guest-sent auth headers are droppedKeys never enter the sandbox, and it can’t smuggle its own key upstream.
Host model storeThe Ollama route is an allowlist: inference and read-only endpointsNo pull/create/delete — closing a tampering path and an egress path.
Host claude CLIRuns claude -p with tools and MCP suppressed, in an empty dir; refuses to serve unless verifiedThe sandbox gets text, not the ability to act on your host through your credentials.
Your LANBridge binds the VM-only IP; Ollama stays on loopbackNeither is exposed to other machines.
Network egressHost-side nftables allowlist keyed on the VM interfaceEnforced on the host, so guest root cannot switch it off. Bulk exfiltration and direct C2 are blocked.
SpendPer-route request and cost budgets at the bridgeA looping agent cannot spend host-held credentials without limit.
AuditabilityEvery API call logged on the hostYou can review what the agent did.

What is not protected

Egress is contained, not sealed

Two residual channels survive the allowlist. DNS: the guest resolves through the host, so data can be encoded into subdomain lookups — low bandwidth, but enough for a key. CDN fronting: an allowlisted hostname resolves to shared addresses that also serve unrelated sites, so allowlisting one effectively permits others. Name-based (SNI/proxy) filtering is the roadmap.

The default profile is not the tightest one. research ships as the default because a sealed default that blocks every real task teaches people to disable containment permanently. No profile except sealed is exfiltration-proof: an allowlisted search endpoint is a data channel. For untrusted input use sealed, or ./kagebox task, which forces it and refuses to run uncontained.

Bounded windows expose more than the agent. research and skills open egress for the duration of one operation. A warden window is scoped to named destinations the host resolves, but an explicit full-VM window opens everything for its duration.

Approval prompts carry guest-authored text. The reason shown to you is written by a process that may be prompt-injected. It is rendered as untrusted plain text, never markup — but approve on whether you expected the request, not on how good the reason sounds. Approval fatigue is the attack the rate cap exists to blunt.

workspace/ is a code-execution path onto your host — through you. The agent writes deliverables there and you open them. A Makefile you run to “check the output”, .git/hooks/*, .vscode/tasks.json, a poisoned lockfile you install — the VM boundary holds; you are the transport. Review diffs before running or opening them in an auto-executing editor.

Bot tokens live in the VM. A messaging bot’s token must sit where the bot runs. It is a scoped bot credential, not your account, but a VM compromise exposes it. This is why the warden’s approval bot must be a different bot, with its token on the host.

The model provider sees your prompts. Cloud backends receive your task text. Use the local backend for private data.

Hypervisor and kernel 0-days. VM isolation is strong but not absolute. Keep your host patched.

Hardening checklist

  • ./kagebox egress profile sealed for any untrusted or web-facing task.
  • ./kagebox verify afterwards — assert the boundary rather than assume it loaded. Every control here fails open, so one that silently didn’t apply looks exactly like one that is working.
  • Keep secrets in bridge/secrets.env (host, git-ignored) — never in the VM or workspace/.
  • Set a messaging allowlist so only you can drive the bot.
  • Review ./kagebox audit after unattended runs.
  • Keep host, multipass and Ollama patched.
