# Egress allowlist — domains the sandboxed agent may reach when egress is ON.
# Egress is enabled by default at `./kagebox setup` (contained by default), so
# add the EXTERNAL sites you trust here, one host per line. The host bridge (for
# LLM/API calls) and DNS are ALWAYS allowed. Open the VM fully: ./kagebox egress off
#
# With this file empty, "egress on" is maximally strict: the agent can talk to
# the bridge (so cloud/local models still work) but reach nothing else on the
# internet — the tightest posture for running untrusted input. It blocks bulk
# exfiltration and direct C2, but NOT everything: the guest can still reach the
# bridge gateway (by design) and the host's DNS resolver, so DNS tunnelling and
# provider-proxied bytes remain possible low-bandwidth channels (see SECURITY.md).
#
# Add sites the agent legitimately needs, then: ./kagebox egress on
# Entries are resolved to IPs and re-resolved every ~10 min on the host, so
# rotating IPs keep working — but CDN-fronted hosts share IPs with unrelated
# sites, so allowlisting one effectively allows others on the same front end.
#
# --- examples (uncomment what you trust) ---
# api.telegram.org
# duckduckgo.com
# en.wikipedia.org
# www.skyscanner.net
# www.google.com
#
# Package mirrors (only if the agent must install things while contained):
# archive.ubuntu.com
# security.ubuntu.com
# pypi.org
# registry.npmjs.org
